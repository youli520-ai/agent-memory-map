# 四层记忆地图设计

## 分层

| 层 | 载体 | 特性 |
|----|------|------|
| L0 总入口 | 单文件地图 | 每轮注入，恒定尺寸；= 热区（每轮必须项）+ 分类树 |
| 大分类 | 枢纽文件 | 指针被拉动时按需读取；同主题条目聚合 |
| 小分类 | 枢纽内章节 / 子文件 | 文件 >150 行时拆分 |
| 确切点 | 条目/坑/参数 | 具体事实 |

辅助层（与地图互补，非替代）：
- **关键词索引**（平铺直查，加速精确命中）
- **探针题库**（人工维护的真实问法+换说法别名+预期承载，检测用词漂移）
- **可达性体检**（哨兵：只报告不修复，处置权在主流程）
- **语义召回**（历史态兜底：检索会话原文而非记忆条目）

## 核心区分：当前态 vs 历史态

记忆条目维护「当前有效值」（权威表，带时间戳与口径标注）；
会话召回提供「历史快照」（过程证据）。
二者互相校验：体检管当前态可达，语义基准管历史态可达。
旧快照在跨月/被取代后成为误导源——因此条目元数据建议携带
`status: current|superseded` 与时间字段（吸收自 mem0/Zep 的字段设计）。

## 容量治理：两级触发

1. **主触发（即时）**：外部监视器盯 L0 尺寸，≥阈值注入执行令，
   agent 当轮执行「地图治理」——合并归组 / 降级休眠 / 淘汰，
   目的地是地图结构内部，不做无差别下沉；
2. **预警层（周度）**：体检容量分级（75% 提示合并归组 / 90% 计入告警），
   给主触发留提前量。

> 设计教训：退役一个自动触发机制之前，先实测它的触发前提是否真被消除。
> 「地图化后 L0 恒定不再增长」是未实测的想当然——合法增量（热区补注、
> 运维指针）仍会累积。

## 事件判定（写入四层）

1. 来源分诊：用户规则/踩坑/新配置落定/偏好表达才评估；
   一次性过程细节交历史召回兜底，不入记忆；
2. 查重四态：new / duplicate / update / append（append-only 审计留痕）；
3. 类型标签：坑 / 决策 / 配置 / 教训；
4. 落位与强度：有承载进承载件，无承载进分类枢纽；
   强度只由用户重提加强（防自我强化偏差）。

## 体检三层

- A 结构：悬空引用 / 孤儿文件（存了但索引找不回）
- B 探针：真实问法走检索路径，三态判定（当前候选/存而不达/已被更替）
- C 地图一致性：地图引用的承载件必须存在、枢纽必须被收录
- D 容量：L0 字符数连续分数，分级告警

探针维护纪律：新增关键条目顺手加一题；体检报「存而不达」时
二选一处置（条目补换说法 or 探针校别名），修完复跑须全绿。
